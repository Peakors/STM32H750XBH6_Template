## 2. 接线

| 调试器 | 核心板 |
|---|---|
| 3V3 | 3V3 |
| GND | GND |
| SWDIO（DAPLink: SWDIO / ST-Link: SWDIO / J-Link: SWDIO） | PA13（SWDIO） |
| SWCLK | PA14（SWCLK） |

串口（不占用 SWD 引脚）：

| USB 转 TTL | 核心板 |
|---|---|
| RX | PA9（USART1_TX） |
| TX | PA10（USART1_RX） |
| GND | GND |

> 💡 TX/RX 是**交叉**连接：模块的 RX 接板的 TX。只看打印的话只接 RX 和 GND 也够。

## 3. 确认调试器类型（cfg 开头三选一）

三份烧写算法（`4.Release/OpenOCD/`）开头都是同样的调试器配置块：

```tcl
# DAPLink（默认启用）
adapter driver cmsis-dap
# ST-Link
# source [find interface/stlink.cfg]
# J-Link
# source [find interface/jlink.cfg]
```

- 用 **DAPLink**：什么都不用改；
- 用 **ST-Link / J-Link**：注释掉 DAPLink 行，取消对应行的注释（同一时间只能启用一个）。

三份算法的用途：

| 文件 | 用途 |
|---|---|
| `FK750M5-XBH6_Internal_Flash_Download_Algorithm.cfg` | 烧 **Bootloader** 到内部 Flash（`0x08000000`） |
| `FK750M5-XBH6_External_Flash_Download_Algorithm.cfg` | 烧 **APP** 到外部 QSPI Flash（`0x90000000`），经典算法 |
| `FK750M5-XBH6_External_Flash_4Wire_Download_Algorithm.cfg` | 烧 **APP** 的四线通用算法（自动识别 W25Q8~512；CLion/GDB 下载走 QPI 4-4-4），与上面那份**二选一** |

## 4. 打开串口终端

1. 设备管理器里确认调试器/USB 转 TTL 对应的 COM 口（如 `COM12`）；
2. 打开串口终端，参数 **115200-8-N-1**；
3. 保持终端开着——烧写复位后的输出马上会出现在这里。

---

## 5. 烧写（两条命令）

在**仓库根目录**执行（Windows cmd / PowerShell 直接整行粘贴）：

**第 1 步：烧 Bootloader（内部 Flash）**

```
openocd -f 4.Release/OpenOCD/FK750M5-XBH6_Internal_Flash_Download_Algorithm.cfg -c "program 4.Release/Bootloader/STM32H750XBH6_Bootloader.hex verify reset exit"
```

**第 2 步：烧 APP（外部 QSPI Flash，两份算法任选其一）**

经典算法：

```
openocd -f 4.Release/OpenOCD/FK750M5-XBH6_External_Flash_Download_Algorithm.cfg -c "program 4.Release/APP/STM32H750XBH6_APP.hex verify reset exit"
```

四线通用算法（自动识别 W25Q8~512 容量）：

```
openocd -f 4.Release/OpenOCD/FK750M5-XBH6_External_Flash_4Wire_Download_Algorithm.cfg -c "program 4.Release/APP/STM32H750XBH6_APP.hex verify reset exit"
```

每条命令成功时 OpenOCD 最后三行应为：

```
** Programming Finished **
** Verify Started **
** Verified OK **
```

> 💡 烧写顺序先后无所谓（两者分别落在内部 / 外部 Flash），但两步都要做：只烧 APP 的话上电不会有人去引导它。

## 6. 成功标志

烧完 APP 那条命令结束后，板子自动复位，串口终端应出现：

```
***************************************
W25Q64 OK,flash ID:EF4017
Jump to the user application in W25Q64 >>>

Hello!

Hello!

Hello!
```

- `W25Q64 OK,flash ID:EF4017`：Bootloader 正确识别了外部 Flash（JEDEC ID）；
- `Hello!`：每 500ms 一条，是 APP 在外部 QSPI Flash 里**就地执行（XIP）**的打印——看到它就说明「内部 Flash 引导 + 外部 Flash 执行」整条链路都通了。

同时 USB CDC 虚拟串口（如果接了 USB 线）会输出 `tick NNN` 计数。

## 7. 常见问题排查

| 现象 | 原因与处理 |
|---|---|
| OpenOCD 报 `Error: init mode failed` 或找不到调试器 | ① 调试器类型与 cfg 不符（回第 3 节改注释）；② 驱动未装（DAPLink 装 WinUSB/Mbed 串口驱动）；③ SWD 线序/接触问题 |
| `target examined ... failed` / DPIDR 读不出 | SWDIO/SWCLK 接反、供电不足、线太长（降低 `adapter speed`） |
| `** Programming Failed **`（擦除阶段） | QSPI 引脚与原理图不一致（本模板算法绑定 FK750 核心板引脚），或 Flash 焊接不良 |
| 串口出现 `W25Q64 ERROR!!!!!` + 乱码 ID | 外部 Flash 状态异常：断电重新上电再试；若用四线算法请确认使用本仓库最新版（旧版命令行烧写后 Flash 残留 QPI 模式，已在 v1.1 修复） |
| 串口出现 `W25Q64 not found, boot aborted.` | Bootloader 能跑但识别不到 Flash：接线/焊接/算法引脚不匹配 |
| 什么都没输出 | ① 串口 TX/RX 没交叉；② 波特率不是 115200；③ 只烧了 APP 没烧 Bootloader；④ 供电不足 |
| `Hello!` 正常但没有 `tick` | 正常——`tick` 走 USB 虚拟串口，不在 USART1 上 |
